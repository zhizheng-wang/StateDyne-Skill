> **10.23 内部后台点—动作预研**：顺向与逆向点搜索完成后，`change_portfolio` 与 `change_action_probe` 读取相同冻结候选并行工作，后者生成后台 action 候选以验证点的可达性，不向用户泄漏动作。已审计放行的 points 阶段接续 actions 时，如原事实与目标未改变，保留 `intervention_frontier_done` 并复用 `action_preflight`，不重复独立选点与组合工作；新的事实更新通过 `update` 路径失效预演。

# 可执行认知系统 · 10.22.0（保留原架构，并改为能力常开）

> 原 10.12.0 工程描述保留，以下默认值与任何旧版“最多三项”限制以 10.22.0 实际运行器为准；详见 [常开执行入口](always-on-orchestration.md)。

## 不是新增一个万能主智能体

程序管理任务和状态，模型完成具体认知操作。所有工作者可以使用同一基础模型，但其实际调用与输入独立。没有永久主思考者把其他候选变成附注；已有贡献先通过来源与结构检查进入空间，再由临时调度、写作、审核比较采用。

```text
                   原始任务 + 已授权材料
             ┌──────────────────────────────┐
             │ 十项独立原料工作：同批可并行      │
             │ frame/system_map/discovery/reframe │
             │ contrast/environment/blind    │
             └──────────────────────────────┘
                         ↓ 全部成果直接入池
              首轮独立边界审核（逐现象 coverage）
                  ├─ pass → 自适应工作选择
                  └─ reopen → 定向关系补建
                                ↓
                           全新独立复核
                                ├─ 补建成功 → 自适应工作选择
                                └─ 仍未解/次数上限 → 明确阶段性结果
                         ↓
      搜索机会池 → 一次调度多个独立高价值操作并行
       深化/外推/环境/迁移/取证/创新/改变/采用
                     ↓ 新增或改变的关系和机会再入池
          前台写作（每项焦点可见处置）→ 独立审稿
                                ├─ blocking → 指定返工 → 重写/重审
                                └─ pass → 真实程序放行
```

这条框架固定来源、权限与成果交付边界，探索操作根据当前发现动态选取。它不是自主修改源码的系统。当前初轮默认九个互补独立原料工作者，且不是工作者数量的认知上限。后续在真正独立时支持按可用并发量批量派发多项任务，不保留旧版“每批最多三项”的认知规定；超过物理并发能力的独立工作进入下一批而不丢失。默认 `max_operations=None`，不再通过固定探索次数宣称认识已经完成。实际作业数量/请求失败/内存/超时保护仅是工程边界，不是认知完备证据。

## 新程序

`run_statedyne.py` 是命令入口，`sd_runtime` 包实现状态、证据工具、工作模式、模型运输与调度。`evaluate_statedyne.py` 单独运行真实模型对照、匿名导出和人工评分汇总。

Python 3.10+，标准库。OpenAI 后端固定调用官方 HTTPS Responses 接口，不使用浏览器 Cookie，也不从用户已登录的 ChatGPT 账户偷取授权。模型由 `--model` 明确指定；没有密钥、没有授权或不支持结构化输出时真实失败，不切成另一个模型。

每次角色调用发送共同内核 + 该角色规则 + 其允许输入，不强制加载全部旧文档。工具继续调用在同一次任务中携带必要 API 协议项；角色之间不复用先前 Responses 会话。私有推理项只在内存中作协议接续，不持久保存其内容。

## 四类数据必须分开

**原始证据**：`sources` 保存原文、出处标签、SHA-256、认识身份、原有精度和是否已被替换。用户说某事，不等于已经客观验证某事。

**现实生成关系**：`claims[].mechanism` 明确输入、条件、转化、中间状态、输出、反馈和适用范围。它说明被解释对象可能怎样工作，不是单纯引用哪个结论。

**认识与探索**：每个候选还有 `epistemic_status`、实际引用段落、声明依赖、替代解释、不同后果。未知有来源类型、信息路线、重要性和关联候选。程序不把 `depends_on` 的认识依赖无环约束误套给现实反馈，时间反馈保留在 `mechanism.feedback`。

**改变与交付**：点、动作、方案是不同类型；动作需引用至少一个独立点。最终候选处置和问题处置均必须完整，写作者不能把未采纳当“从未存在”。排序、心理采用、动作可行性等仍需真实语义审稿，字段存在不证明这些工作有质量。

所有工作产物保存在对应 `jobs`，不是只保留一份不断压缩的主摘要。没有自动图数据库和全语义求解器；当前状态为本地 JSON。

## 结构化契约

唯一机器契约在 `scripts/sd_runtime/schemas.py`；请求文件包含对应精确 schema，避免在多份文档中手工复制漂移。

- `frame`：原料现象账本，绑定逐字来源引文、结果/反差、它为何重要；仅通过独立原始材料输入生成。
- `entry_review`：为每个焦点给出 coverage 状态、可追溯候选关系、中间桥梁、材料中未报告的预测及判别途径；缺口触发真实 `entry_repair` 与新的独立审核。若原映射缺重要现象，审稿者能新增带真实来源的焦点。
- `work`：实际摘要、候选关系、未知、机会、无增量理由；新关系只能标候选/推断，不能自认证为事实。
- `search_plan`：本批一项或多项无依赖的操作、具体目标、机会 ID、预期增量、并行理由与可结束理由；一次调度不是固定多轮检查。旧 `schedule` schema 仅作兼容，不是本版本默认任务。
- `draft`：用户可读答案、完成/阶段/待信息状态、全部焦点的前台可见处置、全部候选与未知的处置、使用的候选 ID。
- `audit`：通过或返工、具体缺口、影响对象、建议修复操作、**全部焦点、候选与未知的检查范围**及剩余限制。

新候选应直接引用当前任务，或通过本任务工具真正读取材料再引用；已建立结论可用 `depends_on` 引用，不能伪称重新读到了其他工作者的来源。

## 已有程序硬检查

**10.4 关键执行门禁**：真实接收六个彼此隔离的原料盲工作（含 `frame`、环境发现与盲挑战），七者可在相同原始资料快照下同批执行，然后运行来源锚定的 `entry_review`。每个重要现象必须被覆盖；审核提出漏掉的焦点必须能追溯引文；partial/open 触发关系补建和新审核。新审核若宣称解释完成，必须引用真实补建工作中新生成的 claim，不能仅复用旧 claim。达到限定次数仍存在缺口则仅放行条件性/未解的阶段性结果，禁止 complete。最终前台焦点解释和独立审稿范围必须完整。`compose` 不设可见问题数量及字符数默认上限（可显式配置单问限长）；提问仍须有真实决策增益，询问数量应由独立判别价值决定。



实际返回存在、输入/产物哈希匹配、合法 schema、来源原文与可见片段、声明依赖有效、动作与点分离引用、当前候选和未知不被静默删除、声称询问的问题确实出现在答案、关键未知未解不能报完整完成、稿件和审核同版、明确阻塞不能 pass、独立调用声明及引用区分、预算、失败保留与模拟标签。

不能硬保证：遗漏候选必被发现、机制是真实原因、不同描述一定语义不同、原生宿主隔离声明一定诚实、引用一定在意义上支持观点、未声明依赖自动被识别、文字中的精度从不虚增、建议一定使人改变。上述由认知挑战、外部证据及真实任务评测共同约束。

## 预算与停机

10.22.0 默认**没有预设认知探索次数上限**（`max_operations=None`），也没有固定提问数或单次总智能体数的认知上限。当前默认单批最多并发 12 项真实无依赖工作（`max_parallel_operations=12`），未进批的重要候选不会被丢弃。独立审核/首轮修复以及 API 请求、并发、作业、文本容量、超时等仍有可配置的技术防失控保护，详见 `scripts/sd_runtime/store.py`、CLI；这些保护只会造成受阻或阶段性交付，不能当作已经找到所有重要关系。不得在任何用户可见质量承诺中把固定计算预算冒充认知完备。

即使探索预算为零，原料盲挑战也已经先于调度完成；此时仅允许有来源的阶段性结果。任务/API预算耗尽或审稿修复用尽会停止，不能生成已放行答案。HTTP 429/5xx 有限重试记入账本；网络超时可能已发生远端计费，不自动复制未知交付状态的请求。失败任务只有显式 `retry` 才建立新尝试，旧原文保留。

## 状态恢复与成果

`state.json` 是共同状态；`jobs/Jxxxx` 存请求、真实输出、工具记录、错误；`api-ledger.json` 记录 API 尝试；`release.json` 标明放行身份；`answer.md` 为已放行前台稿。`draft-only.md` 是未经最终放行的诊断稿。测试替身只能生成 `simulation-answer.md`，不能混作产品答案。

`verify` 检查链与文件绑定。哈希链不是防恶意本地管理员的签名安全系统；不要把它当密码学独立见证。工作目录包含私人原文，应按本地敏感数据管理，不随技能上传。不自动执行方案、点击外部系统或发送消息。

控制器命令使用独占锁避免同目录并发写入。异常退出可能留下 `.controller.lock`；必须确认已无运行进程并备份状态后才能人工清理，不能为“恢复成功”强删活锁。

## 10.6：首次发现重复不得假装独立增益

`sd_runtime.diversity.check_raw_discovery_diversity` 在初始十项真实返回之后、写入首轮认知账本之前，比对 `discovery` 和 `reframe/contrast_probe/environment_scout/blind_challenge` 交付的可观察候选、未知和具体探索机会。若后者只是前者/兄弟工件的完全规范化重复，且不说明**为何经过不同搜索仍没有额外增量**，控制器明确报错，不能用十个回执替代新关系。允许诚实报告“无独立发现”；不为了通过而硬造潜规则或心理历史。比较器不能识别语义换词或证明真实因果，仅提供一种针对假并行成果的工程负对照。

普通 `@StateDyne` 若没有实际执行受控程序，不能声称上述检查已经自动运行；其默认路径在 [portable-discovery.md](portable-discovery.md) 和 `SKILL.md`，同样承担强发现但没有程序硬门禁。
