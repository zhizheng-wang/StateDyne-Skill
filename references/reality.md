# 现实信息：发现、取得、判别、修订

信息循环不等于向用户提问。它包含发现当前不知道什么，读取/搜索/计算可得信息，在不可得处继续条件推断，以及新结果实际修改模型与下游。

## 来源路由

原材料已经给出：实际读取并引用其支持范围。授权文件或系统能取得：用实际工具查取，遵守来源权限。需要公共知识、术语或最新信息：使用宿主真实检索能力并核对可靠一手来源；没有工具就标明未取得，不伪造检索或把一般记忆说成当前核验。可以安全计算/模拟：执行并保留输入假设与结果，模拟不是现实观察。只有用户可能知道：集中提出能改变关键解释、打开新可检验机制、改变预测或行动的问题；新发现不必先翻转动作才能有研究价值。用户也无法可靠知道：保留未知，继续有根据的候选、预测和稳健构造。

新 Python 运行器内建的是已注册 UTF-8 材料的读取、字面搜索和受限算术，**不内建公共网页浏览器、任意代码执行或未授权文件搜索**。API 模式的公共事实缺口必须保留，或由授权宿主另行取得后作为明确来源输入；本方法原文不是领域事实或治疗证据。宿主便携模式仍使用其现有真实网络工具。

## 从证据到判断

先看原文实际比较了哪些共同变化的条件、报告精度与支持范围，再看它能否区分候选。相关、前后变化、单次干预、既有处理下的短期缓解都不是同一种因果证据。相容替代未分开时可保留有力候选，但不能把分量、方向或长期效果说成已识别。

意义、动作、机构规则或用户所说的某个方法尚未定义时，先恢复真实对象，不能挑一个弱版本来证明首选更好。公开使命、惯例、实际筛选、权限与激励分别核验；隐藏动机只作候选。只看成功案例可能无法区分机制，反例与近似条件下的差异也有信息价值。

## 更新不是只加一句提醒

新事实先重开原来的对象、边界和解释范围，再传播已登记依赖。错误原因、排除、排序、采用理由、反馈门槛与方案都应同步修订；不能只把解释改成“可能”，却让旧动作理由无条件保留。

程序保存原文、来源类型与原始精度，检查引用是否匹配已读段落；它不能自动证明引文支持了解释，也不能全面识别正文中的假精确。语义审核负责这部分。未被登记的依赖靠模型外发现和审核继续寻找，不声称程序能找出所有未知。

## 环境与外部来源的实际取得

复杂现实问题中，潜规则探索属于竞争假设：要有独立环境主体与可观察结果的传导，不以使命、机构头衔代替真实执行证据。受控执行器有 `environment_scout` 原料盲角色与 `environment` 定向操作；公开材料须由宿主真实检索，使用 `add-evidence` 记录 URL/标签后才能在后台成为已登记来源，程序本身不伪装网页浏览。


## 面向任何领域的主动取证（10.5）

先问哪个事实或反例能让当前竞争模型产生**不同选择**，再决定使用宿主搜索、API 搜索、注册文件/数据库、计算、现实实验或用户独有的回忆；不要按统一固定搜几次。第一手财报、比赛章程、规则执行记录等应优先于猜测性评论。注意公开资料不全不等于可以虚构隐藏目标或具体权重。公司使命/组织者身份只是生成潜在筛选关系的入口，必须检验实际传导。金融材料应优先检查同口径历史、并购影响、真实现金流、反证与时间截点。

外部工具若不可访问，应明确来源需求和可区分预测并继续条件推理；严禁宣称已搜索。API 托管 web_search 返回的 URL 及引用记录默认是线索，不等于已下载核对原文，也不能拿它冒充 `source_id` 可核验的逐字证据。
