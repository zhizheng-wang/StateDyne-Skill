> **11.2.1 继续推荐与研究记录分离：** “未知仍存在”不等于“尚未调查，也值得立即再查”。成稿所称下一条深入/扩大搜索必须来自**未尝试或新证据重开的**、足以改变解释、目标、干预或动作的方向；已尝试无增量的环境问题与新关系可保留为适用边界，但不能反复用同一句话催促用户。用户随口插话时从实际保存的当前研究账本恢复，而不是从过期的前台推荐快照恢复。

> **11.2 真实接续入口：** 开放任务已经讲完分析或干预点，但仍有可改变结果的真实研究方向时，末尾自然说“下一步可以 [具体动作阶段]；如果想继续找更好的位置，还可以研究 [具体未检验的关系]，它可能如何改变排序”。不能只写“需要可以继续”，也不能凭空制造关系。临时追问先完整回答，再保留主阶段及继续搜索位置；用户明确仅要直接帮助/不想再谈时不催促。没有宿主持久存储时只依据当前实际可见上下文，不假称跨会话保存。

> **11.1 研究状态与对话收尾分离：** 有价值研究机会应当保存，只有用户愿意继续时才需要可见研究邀请。用户明确表示本轮只想得到一个简单办法、不再深入分析时，本轮完整给方法即可；受控 `navigation.quiet_reply_quote` 可引用用户本轮原话抑制强制接续，但不暂停或清除主任务。该引用必须是真实表达暂不继续研究的语句，不能把任意“给我办法”解释成拒绝后续。下一次用户主动继续仍从已审核主阶段恢复。
## 10.26 具体未知决定是否还提供扩大搜索
不是每轮都硬加“扩大搜索”。当仍有经审核值得查、但因阶段目标而尚未追完的不同关系时，末尾可以同时给自然下一阶段和**该具体关系**的继续路径；若没有真实增量不需要提示。后台记录其关联的未知和暂时结论，确保支线问题后也能接续，不把按需追查变成每次重复问用户。

# 对话接续与工作状态：每轮回答后仍知道从哪里继续

此协议处理**任务进展**，不是强制增加用户需要回答的问题。首要责任始终是完整回答用户本轮话语；是否展开下一阶段由用户决定。真实客户端是否显示按钮由宿主控制，技能不得谎称能够强制生成 UI 控件。

## 两种进度始终分开

- **主任务轨道**：任务目标、已经审阅并正式交付的最高阶段（理解/干预点/动作/方案）、被保留的关键证据和假设，以及已经确定的下一阶段。
- **当轮分支**：用户补充一个事实、问一个小问题、纠正词语、询问依据或要求延伸搜索。这是可以独立回答的分支；除非用户明确改变目标或选择另一个阶段，否则**不把分支回答当成主任务重新归零或自动前进**。

用户在选点后提一个小问题，先充分回答，再明确仍可继续到动作，也可留在选点阶段扩大搜索；若该补充真推翻原点，则先解释受影响的改变而不硬复用。分析后的小问题同理。用户说“下一步”应接续**最后审核交付的主阶段**，而非最近一条回答的表面主题。

## 每轮的自然收尾

1. **有下一阶段且用户本轮允许继续研究**：答案末尾自然用一句话提出现在最有价值的下一步，说明可以推进；若本阶段仍有独立可查缺口，允许同时自然提及“继续扩大搜索/核对 X”。不要求用户理解内部术语，不编造成必然需要提问的表单。
2. **小问题或补充**：回答本轮小问题后，依据持久的主任务状态自然承接原研究，别把刚问的支线误作为已经完成下一阶段；不要重发此前完整干预点、动作或长报告。
3. **阶段明确已经完成**：若还有可验证的外部结果，可以自然说以后根据什么现实反馈继续；确实没有真实下一步时允许简短结束，不发空泛号召或固定的“下一步”模板。
4. **用户明确换目标、补充重大新事实**：优先重新审核受影响的模型、成功标准和方案；未受影响的原成果继续沿用，必要时说明新信息为什么改变选择。

## 结构化内部交付

成稿应另行写出后台 `navigation`：本轮是主阶段还是支线、保留的主阶段、合理的下一阶段、自然接续句及可选扩大搜索句。每个拟显示的句子须出现在**本次已独立审核的正文**，而不能只写在发布记录；与用户实际需求不相符的接续必须返工。后台仅存最少任务进度，不存/展示私密内部推理。

受控运行器在发布后将审过的导航写入持久 `task_navigation` 并附在 release 记录，后续新资料与小问题共享。一次新问题（side_question）需要明确标记为临时分支；没有这样的标记时按普通用户新事实/后续工作更新，不擅自猜用户意图。通过 `continue next`，系统从最后审核的**主阶段**决定下一次正式工作；通过 `expand` 保留当前阶段而不是重置为一般分析。

**保证范围**：工程门禁能核验导航字段、下一阶段逻辑、已审文本与记录的一致性，但不能以此证明每个自然措辞都对人有帮助；实际可点击“下一步”按钮仅在宿主支持时出现。


## 更新隔离与可审计工作状态
后续每次实际产生新工作时，应使用不同的工作轮次标识，包括调度、成稿和审核；任务的大版本未改变，不意味着可以复用上一轮相同名字的工作者结果。仅相同输入且未受新证据影响的已审核成果才可选择复用。对于支线引入的新证据，允许在审查证据影响后重新生成相应的动作或选点，不因为需要保持对话接续就无条件使用旧结果。


## 10.29 autonomous routing and non-participation
Normal CLI `update` without an override now calls an independent `turn_router` before mutating any task source. Existing explicit `--side-question` remains a permitted host override. A routed refusal sets `task_thread.user_input_policy=no_repeated_questions_without_invitation`; the controller rejects an audited reply that issues new user questions anyway. The user may later explicitly invite further questions. Side-turn sources are not promoted to main task sources; the last published primary stage and objective remain available over multiple side conversations. An explicit user pause or closure suspends automatic re-entry until they themselves resume. This is an ordinary conversation continuation mechanism, not an unsolicited scheduled agent.
When goal/boundary changes materially, independent assessment reopens the relevant model; explicit replacement must not be treated as minor feedback. Optional expansion remains an actual search route, not a second UI control guaranteed by skill ZIP.

## 10.30 有效下一步与连续搜索

- 同一目标可以沿**已审核主阶段**继续，也可停留该阶段扩大真实关系搜索。真正的新证据可能反向改变原答案或干预点，而不是只新增补充说明。
- 后台保留具体待验证的候选和取得方式（`research_frontier`），跨无关支线不清空；用户明确 `下一步` 时，从上一条正式主阶段推进，若方案阶段已无下一结构阶段但仍有重要研究前沿，则进入这一前沿的深入搜索。没有未完成阶段或有意义的未解关系就说明已结束，不无限催促。
- `我不想提供信息` 不是取消目标，继续利用可用公开证据、材料推演、竞争条件世界研究当前问题，并让真实独立价值搜索再次进行。无证据不许承诺必然的个人结论；已可稳健实施的方案不因缺乏唯一解释而迟交。
- 每次先回答本轮所求，随后在合适时简短说明**具体**下一步（将研究/实施什么、为何可能改变判断），如仍有可查的模型外差异，也可以提供具体“继续扩大搜索”方向。前台不用表格和后台状态字段。不因用户仅插一句话就立刻重述旧的全部分析。

## 11.0 双轨接续
即使已到 plan 且下一阶段为 none，只要后台确有未尝试的高价值生成关系、目标替代或区别性信息，仍显示该关系具体的深入/扩大搜索入口；只有当前答复已完成，不等于模型潜在增量已归零。只有确实存在价值的情况才提示；自动派发需当前用户授权，不以自动后台运行承诺代替。
