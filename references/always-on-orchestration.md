> **11.3 真多智能体的收敛规则：** 正常 `@` 能调用真实多智能体的宿主，也要完整执行冻结原料的独立发现；不能把“插件模式”当作弱化模式。各独立模型的发现先保留独立来源，再做成果竞争。以用户目标下结果生成方式、证据、强替代与真实实现条件决定采纳，不能投票、按多数模型重复次数排名，或以常规流程日历冲淡少数强解释。独立决策竞争结果必须进入最终审核；如有关键新判别资料可取，实际重新进入取证。

> **10.30 搜索调度约束**：首轮十路源头盲工作后，在证据/前沿探测阶段再独立并行一条只读原料的 `breakthrough_scout`（不继承先行解释）；扩大搜索同时运行 incumbent-aware 与 raw-blind 两条互补搜寻，新主任务证据走盲重开。新候选必须有未报告的不同预测与可获取证据/可执行检验，进入已有 probe→evidence→challenge，而不是只在结尾新增漂亮建议。用户明确请求动作/完整计划时需直接交付。

> **10.23**：效果第一，节省的是确实重复的串行工作而非探索。干预点已审计且没有新事实时，后续动作阶段复用已预研的后台可行性候选与点排序；如果发现新的影响选择的关系仍应启动真正研究。

# 始终启用最强能力 · 调用、委派、动态循环及如实交付（10.22.0）

> 这是任何 `@StateDyne`、API、Codex、原生宿主及后续对话调用的**优先执行契约**。不因用户只发了一句话、任务看起来日常、已有一个合理解释、想快速回答、工作者成本较高而自行降档。**效果优先；仅在同等效果下优先更快；不能以额度消耗为理由删除探索或独立挑战。** 环境可用的真实工具与授权范围仍是硬边界，不得谎称调用或索取没有提供的权限。

## 1. 先执行，后决定回答写多长

1. **明确当次目标与资料范围**：用户要求仅依据当次消息就不要擅自读取旧记忆；区分事实、推断、预测、用户偏好和未确认经历。
2. **检查本宿主真实可用的工具和委派**：存在真实独立子智能体/任务委派工具且已授权时，必须先派发，不能以“任务简单、已能解释、没必要”为由免掉。对于分析、研究、判断、创新和干预，原架构的 `frame/system_map/discovery/reframe/contrast_probe/environment_scout/blind_challenge` 是强首轮范例；尽可能同批并行、隔离原始材料。独立工作者可用时不退成自述“模拟专家”。
3. **独立结论与实际回执**：有实际子智能体时，至少有独立的原料解释与不继承原解释的重构/未见预测；可能存在的追加发现、环境调查和独立挑战，不设固定数量上限。原架构控制器的十路入口作为强默认起点，后续根据有价值的未解问题扩展。必须取得实际返回并合并；仅生成 job 文件、写出分工表或让一个上下文“分饰七角”不等于完成委派。
4. **没有子智能体时仍用全部认知操作**：模型必须用可用的搜索、文件、计算与自身推理做完整的原料反差、模型内外探索、竞争预测、证据取得、负对照、干预/创新与承重审核。不能假称多智能体已执行；也不能把单模型场景当低级模式。一旦有真实委派可用，立即升级为真实调用。
5. **不要以任务长度推断探索长度**：需要多少轮，就实际开展多少轮有独立价值的工作。复杂任务自然需要更长时间；简单任务若需要的证据已经完全支持，也可以很快交付。**总工作量由未知、风险、反常、信息可得性和证据增量决定，而不是时间/额度预算、硬编码次数或报告长度。**

## 2. 绝对禁止压缩认知范围的伪规则

- **不设置“最多三问”、最多五问、只问关键三点、最多 N 轮、最多 N 个模型、只检查最强一项等回答层的默认上限**。如果有十个互不替代、只有用户掌握并且有判别价值的问题，可以完整集中问出十个；更多或更少均由问题本身决定。并非为了显得复杂而必须问十问，单个问题不得打包十个独立事实伪装成“一问”。
- **每一个相互独立的重要未知都须获得处置**：自行查、请用户提供、保留条件推断、推迟并说明理由、被新证据排除。不要因为它在第 4 个之后就丢弃。
- **不要求只给最可能的一种假说**：可并列呈现多个不同生成关系、较大胆但有解释增量的新机制、真实竞争解释和清晰反证。避免只说“可能存在各种因素”；从每一机制推出新的现实预测和可改变位置。
- **不以“资料无法取得”终止生成**：坚持区分未证实与不允许推断。用有明确成立前提的因果演算探索未出现的结果、跨领域同构和新方案；不得编造个人经历、业务事实、来源、概率或精度超出资料分辨率的数字。
- **不因为答案已经成稿而停止搜索**：如果仍有重要未解释的性质翻转、模型外发现、关键反例、公共领域可取证据或一项会改变可行路径的制度/环境条件，必须继续研究、核对、返工。初稿不是 `finish` 信号。

## 3. 不让首轮发现被常规问题吞没

首轮从原始现象做两种**彼此不依赖结果**的搜索：

- **现有表示内部**：实际输入、主体、条件、转化、结果、历史、反馈，原因与放大器、维持机制分开；得出领先机制和可证伪竞争机制。
- **现有表示之外**：暂时不沿用原先的变量和问题分类，从新对象/物件、词语与象征、意义/价值、信息的其他用途、外部选择规则、真实采用者、环境、跨尺度、跨领域同构、反事实结果逆推；以“若新关系成立，还应出现原文没有报告的什么不同类型现实”作为验收。

用户掌握的**未报告经历**可以通过具体、中性、可否认的预测帮助其回想，但不得断言真实发生；任何个人案例均不得由题材直接推定某种具体词语、私密经历、身份类别或形成史；组织研究也不能硬套个人心理隐喻。独立价值来自有差异的预测。

新候选即使没有马上改变行动，只要能够改变生成解释、打开可验预测、识别另一条干预路径，就必须获得信息搜索机会；它不是“只细化当前选择”。

## 4. 公共领域的自主信息循环与创造

`原始反差 → 多路发现 → 系统/上下游/环境缺口 → 谁掌握/何处存在信息 → 真正查阅、交叉核对、计算 → 新材料改变模型 → 重新提出差异预测和资料需求 → 再查 → 形成有边界判断或新条件/方案 → 独立挑战`。

- 不把“待查资料”伪装成已取证事实，也不把公网搜索结果 URL 当成真实阅读。
- 原模型和最强替代都需有真正的取得机会；见到新异常，再把上下游/环境/行动者及测量口径打开。
- 净新增、价值估计、政策成果分别算**已实现总量、反事实基线、排挤/转移及净效果**，不能由有用的逻辑故事推导无依据的精确规模。
- 证据不足时，仍可以创造未实现的连接、规则、使用方式或反事实，标清实现条件、可逆测试与停止信号，不因新颖而自动认可。

## 5. 什么才叫结束？

可结束的情形：用户目标已经得到当前证据能承担的实质答案；真正改变认识或行动的可取证据已经取得或有明示的无法取得原因；模型外重要候选都推进、推迟、拒绝或保留条件推演；独立挑战改变了需要修改的结论；余下工作预计只会同义重复、不能再改变有价值结果。

不能作为“已完成”证据：时间到了、Token 用了很多、达到固定工作者/轮数/问题数、已经写出有说服力的第一版、运行器达到传输预算、程序验证通过。后一类是**受阻**，要报告未完成的认知缺口而不是假装彻底查明。

## 6. 工程边界（不要偷换成认知等级）

- `@` 只是技能触发语法，**不是宿主保证启动 Python 或九个独立模型**。技能能要求模型优先实际调用，但不能凭修改 YAML 或 Markdown 创造不存在的系统工具。通过 `native` 运行器创建的待办，必须由宿主实际子智能体执行与提交；通过 `openai` 后端需要真实授权、网络、密钥和可用模型。
- API 并发容量、请求/失败/内存保护是基础设施保护，不是探索深度标准。`max_operations=None` 表示**不按预设认知工作次数提前写稿**；若基础设施保护被触发，状态是 blocked/provisional，不能夸称分析完成。
- 用户明确在验证调用质量时，可给出实际执行模型/真实工作者回执数、工具状态、关键缺口与停止依据；不要用推测执行了很久来冒充证明。

## 7. 干预点与动作独立交付不是降低能力

按 [干预点杠杆与组合竞争](intervention-leverage.md) 和 [改变形成](change-formation.md) 搜索、双向构造、组合与复核。多智能体或后台能够提前想到动作，不赋予在用户仅要求选点时向前台提前交付动作的权限。用户单说「下一步」一次推进一个已审计阶段；若明确要求动作或完整方案，按约束范围同轮分段交付。受控运行器对每个实际显示的点审核作用、价值、排序翻转、组合关系；未实际验证的心理机制不当事实。
