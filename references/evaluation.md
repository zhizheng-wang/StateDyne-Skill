> **10.15 验收“九问 vs 七问”时，先看覆盖和认知增量，不看数字**：对不同表达的同一陌生案例，锁定各轮披露前已明确预测的未报告现象，分别统计独立机制发现、错误因果晋级、隐私暗示、同义问题、用户真实答案对模型的修正、干预点排序变动与新增操作负担；同条件重复多次报告分布和失败例，不能挑最好一次证明稳定。已有的演示材料可作回归，不可代替陌生盲测。还须区分普通 ChatGPT 技能、受控 API 调度器和用户从其他 AI 复制的回答；不同执行路径的耗时并不证明提前做了完整选点。

## 10.14 新验收：自然对话中提前预测，与事后“说中”严格分开

对相同初始材料，先封存模型**在用户后续揭露前**生成的另一类现象预测和自然辨认提示，明确它的反面世界；再在独立阶段给用户后续事实，评分预测是否**具体、重要、可否认、出现得早**，以及后续信息是否真正改变模型。事后复述用户提供的专有细节不得计作提前发现。其他 AI 代写的用户回答只能作为转述，不能自行添加或否定未确认的私密信念。

加入不含隐秘关系的负对照、多模态/领域差异、完全不能恢复历史的样本和纯取证金融/软件任务；真实用户只有一次口头叙述时，不应强迫主动找图或诱导回忆。比较 10.13 / 10.14 / 同一底模常规强提示，在相同原始材料与相应工具权限下至少多次重复；分别报告首次发现质量、错误推断率、用户问题负担、阶段越界率、可读性、独立动作质量、算力调用数与耗时。评测没有运行时不得声称新版真实质量已经提高。

## 10.13 跨任务证据承重验收（不能用程序测试代替）

验证时应把初始事实、后续才透露的关键消息与评估准则分离；同一底模、工具权限、研究截止日期与预算下做盲测。比较：首轮是否主动发出能打开另一种关系的可验证探针、是否复核影响结论的来源/口径/计算、是否自主识别 DCF/逆问题的多解性、是否认真比较成熟强替代和无新增动作的路线，以及新反馈是否真的修订了结论。因人的偏好与价值没有明确报告时，未知要保留而不能被描述为已证实。额外 token/调用次数/审核字段完整均不算获胜；必须追踪被证实的独立发现和真实改变。见 `examples/load-bearing-cross-domain.json`（**合成任务，不是实测结果**）。

> **10.13 独立结论承重审计**：重要判断必须区分事实来源、派生计算、关键口径和未经证实的桥接假设；比较强反例/竞争世界、时间截止与结论翻转条件。读取 `load_bearing_audit` 的重大挑战和实际已取得或未取得的证据；不因报告的叙事完整就放行，也不因此一律退回空洞谨慎。尚缺重要事实应进入取证/条件推演，不把用户私有经历或不可观察动机编成事实。对主要量化结论复算并明确假设。改变任务还需比较新的行动是否以无依据的价值/动机推断为前提。

## 10.19 实际增益验收（含成本，而非只比报告长度）

先把实际用户会在后来透露的事实或未来才可观测数据**锁在求解者材料之外**，封存第一次输出的具体新预测、反例和时间。旧开发案例只能作回归，不能冒充未见任务。用同一个基础模型、相同截止日和相同工具授权，比较普通强基线、StateDyne 和可选的第一性原理/批判式强提示；不能把额外模型请求或独立工作者数量视为质量本身。

已完成授权的真实 API 测试与独立盲评分后，可运行：

```bash
python scripts/evaluate_statedyne.py paired-diagnostics --review ../blind/review.json --key ../blind/keep-from-reviewer-key.json --samples ../eval/samples.json --reviewer reviewer-A
```

它按相同 `case_id` 和 `repetition` 配对普通基线与 StateDyne，报告各评分维度的增减、遗漏/失败样本、耗时/Token/模型请求成本比；不会生成真相标签、不会自动认定统计显著、不会把缺失样本静默删除。单次对照不足以证明泛化，尤其需要「没有任何深层隐藏关系」的负对照、无需新方案的成熟强基线、以及模型最初问题表示就是错的正向对照。重度研究还要单独检验可复现来源、估值模型敏感性和创新净新增。

# 真实模型评测 · 10.13.0

评测对象是可观察的自主发现、取证、生成过程、不同预测、干预/动作/方案与反馈修订，而不是“有多少条规则”或模型自称认真检查。工程自测是必要的正确性检查，但不是能力证明。

## 三层结果分别报告

程序与协议测试：可以用明确标记的模拟输出检验状态转换、错误拒绝、来源、返工及预算。不能计入深度、创新、信息发现率。

真实模型测试：实际调用选定模型，保留首次失败、实际模型标识、输入、材料工具记录、每项产物和消耗。模型看完自己的答案给自己评分，不足以证明质量。

真实产品端到端：在最终安装的 `@StateDyne` 宿主上确认入口加载、工具、独立会话、权限与前台交付。API 接近的流程不是产品环境的替身证明。

## 可执行的真实 API 对照

```bash
python scripts/evaluate_statedyne.py run --help
python scripts/evaluate_statedyne.py run --cases examples/public-cases.json --out ../statedyne-evaluation --model YOUR_ACCESSIBLE_API_MODEL_ID --allow-api --repetitions 3 --arms baseline,statedyne
```

使用已安全配置的 `OPENAI_API_KEY`。没有授权或密钥就失败退出，不生成伪测评。`--repetitions 3` 仅是命令示例，不能据三个样本宣布稳定；正式样本数由失败容忍度、任务差异与不确定性决定。

`baseline` 是相同模型、原材料和可调用资料工具的普通强提示；`statedyne` 是本版受控执行。二者预算/调用数不同，必须同时比较原始质量和计算消耗，不得把更多计算全部归因于方法。需要时另设计等预算基线。

可增加 `legacy_prompt` 并提供 `--legacy-skill` 指向旧包：它把旧入口和指定核心规则加载为一次提示对照，**没有复现旧版完整宿主调度、脚本执行或 @Skill 加载**。报告明确其近似身份，不称严格旧版本端到端。

`cases` 是严格输入列表，每项只允许 `id`、`task`、`materials`（每份 `label`、`text`）。预期答案、评分细则和后续隐藏信息不在 solver 输入里。随包四例是开发用公开合成例子，不是未见题；`reviewer-only-rubric.json` 只给评审，不能作为材料加载。

## 如何测信息循环而不是只测长回答

先给初始材料，把后续关键线索放在评审侧。除了最终文稿，还要读取原始 `frame` 焦点、盲挑战、`contrast_probe`、每一轮 `entry_review.coverage`、实际 `entry_repair` 新产物和 `trace` 回执，检查在模型尚未看到答案前，是否已自主构造出与表面机制不同的预测；区分「发现了桥梁」和「只是问用户还有没有别的原因」。评价是否自主提出有区分价值的共同关系、跨对象/环境的预测或开放问题，不要求猜中某个个人词语。没有提示前提出才算自主；知道后再复述不算。

对带有明显正负反转的合成样本，检验模型能否区分「没有正向吸引」和「生成强烈负向评价」；同时必须有物理因素已足够解释的负对照，不能因谈身份、性、潜规则就加分。可见提问不仅评数量，还评判别价值和负担。

对于分散但可读取的信息，检查实际读取和引用；对于不存在或用户不知道的事实，检查是否保留条件推断，而非停止工作、反复追问或编造过去。加入没有隐藏机制的负例，避免奖励逢题都讲深层动机。

当前 API 评测入口主要支持单次任务、多操作运行。受控的多轮信息揭示需要额外的真实用户回放驱动：按固定规则使用 `update` 逐步供给，并记录每条信息出现前的产物。**尚未实现一个能自动扮演真实用户、可靠判断所有自由提问的评测器。** 不能用模拟用户按预期答案补词来证明技能自己发现了线索。

## 匿名评审与失败保留

```bash
python scripts/evaluate_statedyne.py blind-export --samples ../statedyne-evaluation/samples.json --out ../statedyne-blind
python scripts/evaluate_statedyne.py summarize-scores --review ../statedyne-blind/review.json --key ../statedyne-blind/keep-from-reviewer-key.json --reviewer reviewer-A > ../statedyne-score-summary.json
```

核对 `--help` 中实际参数。匿名输出和身份密钥分开放置；答案文风仍可能暴露条件，不能宣称完全消除了识别风险。失败样本也进入清单，不能只送成功长稿给评审。

人工评分要求维度 0–4 或无法判断 `null`，以及具体证据说明与评审身份。各维度分开汇总，不凭空加权一个“综合95分”。可使用其他模型辅助审阅，但程序无法保证评分者独立，人类仍需校准关键分歧。

优先比较：自主发现的独立价值、错误关系和过早闭合、信息效率、用户纠偏负担、改变可行性及可信性的生成、相对排序、与成熟强路线不同的有效构造、修订是否影响下游。复杂度、候选数量、文本长度和“很新颖”不单独算改善。

## 发布结论

`verification` 只报告本次确实执行的工程/协议检查。没有真实模型与宿主回放结果时标记未验证；不得从程序 PASS 推导效果 PASS。未来有实际测评时，保留任务来源、允许信息、每次首次输出与失败、模型身份、工具边界、采样方式、预算和评分方法，再讨论泛化和稳定性。

## 10.5.0 的新增能力验收：发现质量与决策效率分开测试

对同一道多轮任务分别保留：提示前自主发现、后续用户提示后重组、主动查取、决定提问的真实差异、从解释转向点/动作的适当时机。尤其检查**用户说“直接给我怎么办”后是否在当轮独立呈现并比较干预点，然后给出动作与方案**，而不是继续追已经不影响行动选择的历史未知。针对行为改变要检验是否考虑旧状态的价值、改变的预期损失、可信起点及反馈保持；不能为了得分每次强加“隐藏保护动机”。

强评测应有未知但不影响选择的任务、缺少决定性事实必须暂停的任务、用户完全不知道资料但可公开查询的任务，以及应当推荐“不新增动作”的任务。不要只奖励提问多、行动建议多或逻辑链长。能力比较需记录同模型同工具成本与耗时，观察“每次真实增量所花的时间”以及与模型裸答的盲评差异。程序中的交付映射与未知决策字段可以验证**工作被执行**，并不能自动评价哪条干预真的有效。


## 10.5.0 新增消融：广泛搜索是否带来真实认知增益

对用户无法代替 AI 取得资料的现实研究，加入需要查多个相互独立的一手来源、相互冲突的解释与实际反例的任务，确认带 API web_search 的运行轨迹是否有**真实工具调用**，且不能用搜索结果标题替代原文事实。比较：普通同模型、10.4、10.5、关闭 frontier_scout、关闭 evidence_scout。必须同材料与权限，记录额外模型预算，才能讨论二次搜索是否值得。

在已知后续线索但对求解模型隐藏的厌恶/个人行为案例，重点检验能否主动提出跨对象或语言线索的开放问题，不因为提问多就加分，也不因为寻找性、隐性规则、价值观就加分。负例中没有隐秘联想或潜规则时应不强加。关系推导与来源身份需分开计分；不必每句话叠“可能”，但重要因果推断必须清楚标识根据。

评估两级召回：既有候选内部事实取得，以及跳出当前表示找到模型从未主动列出的竞争关系。若新版本仅让答案更长、模型调用更多，却没有增加正确的新预测、可查证据或更优点/动作/方案，其成本增量不得视为能力改进。

## 10.6：高要求开放任务的默认入口与重复发现负对照

- 用尚未暴露后续线索的个人、工程、金融、组织、机制创新任务，以及不需要深层隐藏解释的负对照，比对普通强模型、10.5、10.6 和受控引擎：是否在用户提示之前提出独立生成机制、新现象预测或值得实际取证的事实，假阳性是否增加。
- 不能因为题目是日常、短句、情绪或个人生活就用浅层条件列表代替深层搜索；但也不能因为新增规则而必然作出性、身份、病理或潜规则的猜测。
- 模型输出的“不同分支”必须有实际执行回执（受控）或诚实承认是同一模型的不同搜索（便携）。`diversity.py` 只识别可观察的高度重合，**不能**证明跨领域洞见的质量。检查受控拒绝直接复用候选且未给有效无增量理由的负例。
- 盲测必须记录首轮是否发现关键关系、需要用户补全的次数、候选去重后独立价值、工具实际取得的资料与相同预算下的时间成本；只看工程通过率不构成验收。


## 10.7：统一能力标准与宿主适配的一致性评测

- 同一原始任务分别在纯 `@StateDyne`、可用宿主工具、可用独立工作者的环境执行。比较的是**发现机会是否被实际使用**：领先解释之外的候选、跨场景新预测、实际可得证据、后续干预点与创造性条件；不得把某宿主描述为天然较低的认知质量等级。
- 将问题表达难易与实际内在复杂度正交排列：短口语但有深层未知、长专业文字但主要是直接提取、公开研究需自行找资料、普通改变任务需生成价值与采用路径。验收看是否使用与实际未知相称的高价值认知工作，而不是一律回答很长或固定派出六个智能体。
- 对相同能力目标，分别记录是否真的有模型工具调用、模型外新候选、独立可区分预测、证据来源、信息获取成本与误推断。真实多工作者并行与单模型多角度搜索不可假称等价执行；比较总结果质量与资源消耗。
- 本版本的规则与程序回归测试仍**不能**证明真实 GPT-5.6 发现率提升，必须另行在未曝光题目及真实宿主上运行。
