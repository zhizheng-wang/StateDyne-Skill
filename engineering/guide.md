# StateDyne 10.0.0 工程维护

## 活跃入口

优先阅读 [README](../README.md)、[执行器](../references/executor.md)、[宿主桥](../references/host-bridge.md) 与 [评测](../references/evaluation.md)。认知共同内核是 `references/core.md`，每个真实调用只加载对应 `references/operators` 角色。

这次改变的是输入隔离、候选准入、接续、调度、来源检查、阶段转换和可复现评测；不是只把旧规范写得更严格。`scripts/sd_runtime` 是实际执行代码，不调用旧记录工具冒充模型调用。

## 变更规则

先定位失败发生在能力、资料取得、上下文边界、调度、交付、审核还是宿主适配。为可判定缺陷增加最小回归，再改实现。语义失败另保存真实输入/输出并使用未见题复测，不能让同一编写者给自己的解释打高分后宣布提升。

重要字段变化需同步机器 schema、角色返回要求和迁移说明。程序的“非空 transformation”只能拦空字段，不能证明真实展开了转化；语义审稿和案例评审必须明确这一点。拒绝隐含升级事实身份、不能静默丢候选或未知，也不能以假精确填满关系图。

不为单一个人案例全局预设心理机制。问题类别可以触发专门操作，但回答仍必须由允许的原材料、一般知识和明确推断共同支撑。改变意愿可先被认识促成，也可由低风险的新体验反过来生成，不能统一成说服脚本。

## 兼容与归档

原六脚本原样保留，只支持原各自格式；它们不写新运行器的 `state.json`。`history/9.9.0` 保存被替换的九份执行文档原文，全部标为 archive，不再默认加载，也不是本版现行约束。原方法和原工程规格的字节身份保留在来源清单中。

旧规格/归档的固定阶段与本版活跃入口发生冲突时，以 10.0.0 入口和执行契约为准；方法语义仍保留。不要通过把归档全部重新加入每个智能体上下文来“保证不漏”，而应按具体缺口读取必要概念。

## 验证与再打包

```bash
python -m unittest discover -s tests -v
python scripts/validate_skill.py --strict-bytes
```

修改完成后更新 `references/source-map.json` 的 UTF-8 文件库存、字节/字符/行数、SHA-256、来源身份和加载配置；不只改版本号。去除所有 `__pycache__`、运行目录、密钥和私有评测材料。ZIP 内仅保留一个技能根目录，不把工作数据一起发布。真实模型测试输出放在技能外。

本次验证与真实模型验证必须分开。实现可用后仍需在目标 API 模型与真实 @Skill 宿主上运行，观察协议兼容性和认知表现，不承诺用户目标已经稳定达到。
