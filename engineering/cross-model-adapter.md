# 跨模型部署与盲评操作：同一质量，不同宿主（10.28）

本页是**实际操作指南**，不是另设模型质量档。`SKILL.md` 是统一入口；每个 worker 的 `instructions` 在受控运行器中均加载 `cross-model-contract.md` 与原有核心协议。便携式 `@` 对话由宿主实际支持的工具决定执行方式。**ZIP 不会自行赋予模型委派、浏览或私有账户权限。**

## 宿主能力准入

1. 先检查能否实际创建真正隔离输入、独立模型调用并取得回执的工作者。可用且已授权则优先并行派发互补、独立于已形成主稿的候选与挑战；仅生成角色文字或待办 JSON 不算调用成功。
2. 无独立模型工具时，单模型仍执行相同的现实研究、竞争假说、模型外发现、取证、反向挑战和阶段控制；诚实说明不是多智能体独立验证，不可通过设为“轻量模式”放弃有价值的探索。
3. 将用户明确限制的资料与用户当轮实际提供的原文作为真实输入范围。不得因另一模型声称自己看过更多内容就悄悄注入历史会话。若原文没有的具体经历后来才由用户补充，必须标注其先后；前一轮问出类别不等于已经预测了该具体事实。
4. 核验不以“开 max”或“极高”作为完成证明：是否发现真实新机制、是否有独立可证伪预测、是否在新证据下修正、是否满足多条件共同结果、是否有来源/定量验证与行动改变桥，才是放行依据。

## 不同模型常见两种失败

- 善于讲故事的模型：重点退查形成史、特定动机、隐形规范、历史扩散、行动会形成习惯等是否为已观察事实；缺乏事实时可以提出**有区别性预测的强条件模型**，不能写成确定起因。不要用缩短输出或压掉新意解决这个问题。
- 谨慎克制的模型：重点退查除了现有多个常见影响因素之外，是否已真正尝试新的关系表示、反常机制、跨尺度/领域迁移以及强候选所暗示的**具体未报现象**。可以无新增，但要有实际竞争与无新增理由；不能以“无法百分之百证明”为由不研究。
- 所有模型：各条件分别符合不等于**同一单位同时符合**；有多个好动作不等于改变的是已选的杠杆点；多个独立标题不等于多个真实独立工作者；已审核下一步不因一条支线问题丢失。

## 五模型或更多模型的共同评测

固定同一版 ZIP、原始问题、信息截止日、材料权限与评分任务；分别记录模型/版本、宿主、有无真实隔离工具、实际回执数量、取证工具来源与执行时长。至少分开评估：

- 首轮独立推导的新增**具体且可证伪**现象（在用户补充前封存），及后来哪些得到支持、证伪或仍未知；
- 用户需要补充的信息询问质量；外部证据取得、明确无法取得与返工情况；
- 多个强机制的竞争、适用界限与何处会改变结论；
- 用户成功目标的必要条件同一对象交叉闭合及原始数据准确；
- 干预点的独立杠杆、组合效果、动作匹配、负担及与零动作竞争；
- 正确延续已发布阶段、可选扩大搜索和自然表达。

若某宿主没有浏览/并行能力，不把结果说成相同工具条件下的优劣；对比认知回答时，必须区分工具带来的收益。不同模型得到不同观点不自动算不稳定，除非事实、口径、假设或证据的区别解释不了差异。不要让已知个人故事的词语、评价层次或特定城市/企业条件成为通用核心的默认答案。

本地 10.28 单元测试只测试协议、数据结构、状态和合成反例。真实跨模型质量、盲测正确率、结果稳定性及提速必须由外部试验说明，不能从通过测试推出来。
