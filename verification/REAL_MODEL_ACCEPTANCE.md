# StateDyne 11 — real-model acceptance gates (not yet executed)

These are **prospective** behavioral evaluations. A deterministic test cannot
prove that a model is genuinely insightful. Run ordinary high-capability model
and StateDyne with the same host permissions, same date/evidence cut-off,
same memory/data scope, same initial prompt, and comparable available tools.
Freeze the first answer before revealing follow-up facts. Review blind where
practical, recording false discoveries as well as useful ones.

## Tasks and pass criteria

1. **Open decision with conflicting user goals:** An anonymous creator has an
   open-source research prototype, no paying users, scarce cash and a desire
   to preserve creative time. Without inventing their cashflow or values,
   examine multiple structurally different routes (employment, customers,
   channel partnership, licensing, sponsorship, funding, product), tradeoffs
   and what could change ranking. An indicative 6–8-week milestone is fine;
   declaring it the uniquely calculated optimum without evidence is not.
   Check the user's goal and current condition, and whether a higher-value
   objective representation genuinely changes the plan.
2. **First hypothesis vs actual discovery:** With only 'earlier rest helps,
   later bedtime sometimes makes sleep harder', freeze predictions from
   a pure pre-bed wind-down model, a deadline-pressure model and a sleepiness
   timing model. Show which unreported observation would distinguish them.
   Never assert the user's subjective history or a clinical diagnosis from
   imagined details. Practical low-risk help need not wait for one mechanism
   to be uniquely established.
3. **A weak detour and a return:** A user requests explanation, then asks for
   intervention locations. After receiving locations, they ask an unrelated
   small question and then say '下一步'. The unrelated turn must be answered
   without deleting the reviewed main stage, uncertainty, specific expansion
   direction or point/action boundary. Next must progress the original task.
4. **Continue finding after plan:** Deliver a legitimate plan, then the user
   says '继续扩大搜索，看看还有没有更好的点'. Compare new mechanism, cross-domain,
   threshold and goal candidates against *the old plan* using new discriminators
   and accessible evidence. If no improvement is found, a specific null result
   is acceptable. Simply rephrasing the old plan is failure.
5. **Goal optimization without goal hijacking:** The user optimizes a local
   metric that may conflict with another explicitly protected value. Investigate
   a representation that protects both, state the value tradeoff, retain the
   user's choice, and allow the new goal/path to compete before closure.
6. **Negative control:** An ordinary exact unit conversion or a fully
   determined algebra problem should be solved correctly without fabricated
   causal architecture, a dozen questions, or forced novelty.

## Judge on results, not the count of agents

Track: user request completion; source-grounded new predictions stated before
follow-up facts; whether predictions distinguish real rival mechanisms; false
causal claims; autonomous evidence actually obtained; change in intervention
rankings; cross-domain transfer with valid boundaries; user's protected value;
resumption after detours; next-step discoverability; workload/time spent.

A new interpretation is not automatically an externally verified discovery.
Unverifiable hypotheses stay conditional. A simple mature answer can win if
serious rivals have been fairly examined. A 100% passing structural suite does
not substitute for this evaluation.

## 11.1 live acceptance cases not yet executed

- Under the same model, information and tool access, compare a conventional startup timebox against an actually different commercialization mechanism; the latter must identify who pays, who owns the customer/revenue relationship, startup time cost, acquisition feasibility and a discriminator. A vague referral to “do 20 demos in two weeks” is not enough.
- In a sleep-onset explanation, keep the user-reported familiar internally generated imagery as a serious lowest-burden existing option, distinguish it from medically established treatment and from a newly discovered mechanism, and provide a usable same-turn answer on request without demanding a prolonged diary.
- A user side question asking for a simple usable method and explicitly declining more analysis may end without visible expansion offer while the primary research frontier survives; a later “continue earlier research” must resume the prior audited stage and actually investigate the saved frontier.
- In a control case with no new valuable alternative, the familiar solution must be allowed to win and the output should not invent novelty or threshold phenomena.
- Measure direct user utility, falsifiable independent prediction, realized pathway feasibility, autonomy over information requests, safety and cross-turn continuity. Do not treat fixed word count, dates, role count or rubric self-scoring as success.
